# Upstream and distributed artifacts

This flake names upstream rather than carrying it: `pin.nix` records a release version and each platform tarball's fixed-output hash, and the tarball is fetched only when a derivation is built, so evaluating or promoting this repository conveys no upstream code. Building `packages.<system>.code-server` and serving it is a conveyance, and the install phase copies the release tree verbatim with fixup disabled and no patch applied, so every notice below reaches the recipient inside the output at the path upstream shipped it. Identifiers come from the built output at pin `4.143.1`; the closure identifiers come from nixpkgs' recorded `meta.license` at `5adc50831c259f87faeb09ddf930d43597197473`, which is that distribution's accounting rather than the packages' own statement.

- **code-server 4.143.1 — [MIT](https://spdx.org/licenses/MIT.html)**, `Copyright (c) 2019 Coder Technologies Inc.`, read from [upstream's `LICENSE` at the tag](https://github.com/coder/code-server/blob/v4.143.1/LICENSE), which nixpkgs records under the same identifier. MIT's condition on a copy travels inside the output: `$out/LICENSE` is that file byte for byte, sha256 `872184c17fe5a3379da02acd21949ea2fcf4793bd4a3b920a96ba8b147741745`.
- **[Upstream's own component notices](https://github.com/coder/code-server/blob/v4.143.1/ThirdPartyNotices.txt)** — `$out/ThirdPartyNotices.txt` names each component upstream drew from, with version, source URL and the text of its terms. Beside their own packages sit 244 further license files under `$out/node_modules` and `$out/lib/vscode/node_modules`, 248 license and notice files in the output.
- **Attribution notices** — seven files of the kind Apache-2.0 §4(d) sends with the work they accompany: five under `$out/lib/vscode/node_modules/@microsoft/`, plus `@vscode/deviceid/NOTICE.txt` and `vscode-oniguruma/NOTICES.txt`. Each of those packages declares MIT for itself, and which incorporated Apache-2.0 component each notice covers is something we have not determined. There is no top-level `NOTICE`, because code-server is MIT rather than Apache-2.0.
- **Bundled extensions** — every directory under `$out/lib/vscode/extensions` declares MIT in its own `package.json` except `copilot`, whose `SEE LICENSE IN LICENSE.txt` resolves to a Microsoft MIT text shipped in that same directory.
- **The bundled interpreter** — `$out/lib/node` is upstream's prebuilt Node.js `24.22.1`, and it, not the consumer's nixpkgs, runs the server. The project publishes it under [MIT](https://spdx.org/licenses/MIT.html); no license text for it exists anywhere in the unpacked tree, so whether the notice obligation for that prebuilt binary is satisfied is upstream's release packaging, unverified here. The components it bundles statically — ICU, OpenSSL, zlib, zstd, SQLite and the rest — are Node's packaging too, not something this flake selects.
- **Copyleft found in the tree** — `jschardet`, [LGPL-2.1-or-later](https://spdx.org/licenses/LGPL-2.1-or-later.html) at `$out/lib/vscode/node_modules/jschardet/LICENSE`, matching the identifier its own `package.json` declares; and, through the bundled `terminal-suggest` extension (itself MIT), the reproduced terms of fish-shell, mostly [GPL-2.0](https://spdx.org/licenses/GPL-2.0-only.html), and of zsh's shell functions, partly GPL — both in `ThirdPartyNotices.txt`. `$out/node_modules/argparse/LICENSE` matches a search for the GPL name and is the Python Software Foundation's text, granting nothing copyleft. This inventory came from searching the built output rather than auditing either dependency tree component by component, so the absence of anything further is unverified rather than settled.

The flake's remaining outputs — `update-version`, `update-branches`, `formatter`, `checks.formatting`, and `update-version.sh` in this repository — carry no upstream code: the script reads release metadata and prefetches hashes without ever committing upstream content.

A built output also brings a runtime closure of 37 store paths: this derivation, `nodejs` 24.21.0, `bash`, and the 34 behind those two, several packages contributing more than one output (`libuv`, `zlib` and `openssl` each a `dev`; `zlib` a `static`; `openssl` a `bin`; nodejs an `npm` and a `corepack`; GCC a `lib` and a `libgcc` under the `gcc` name plus a second `libgcc` under the `xgcc` name). `libuv` is the widest union in the closure, and nixpkgs arrives at it from three files libuv ships: `LICENSE`, the Expat text; `LICENSE-extra`, the Joyent grant plus the externally maintained libraries, which is where the ISC and BSD-2-Clause legs come from; and `LICENSE-docs`, whose text is Creative Commons Attribution 4.0 International and whose name is the only statement of its scope upstream makes. The two libuv paths in this closure are a `lib` and a `dev` output holding `lib`, `include` and `nix-support`, and neither carries any Creative Commons text, so the documentation that leg governs is not what we convey. Every leg of that union is marked `free = true` and `redistributable = true` at the pinned revision, so nothing in the closure is flagged non-free by the distribution's own record; a revision that read the CC-BY family differently would be worth re-reading on a bump.
